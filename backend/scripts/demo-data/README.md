# Demo property data (local development only)

`seed_demo_properties.py` creates six complete properties in a **local** backend through the admin API,
the same way the dashboard does: every wizard field, unit types, amenities, nearby places, four photos,
a PDF brochure and MP4 walkthrough videos, then the workflow (published, approved, pending review,
rejected). Nothing is added to Flyway migrations, so other environments never get this data.

```bash
# Backend running locally with the dev profile (cookies without Secure: AUTH_COOKIE_SECURE=false, the dev default)
cd backend
SEED_ADMIN_EMAIL=you@example.com python3 scripts/demo-data/seed_demo_properties.py
```

- The admin needs `ADMIN_PANEL_ACCESS`, `PROPERTY_CREATE`, `PROPERTY_CREATE_WITHOUT_SUBSCRIPTION`,
  `PROPERTY_LIST_ANY`, `PROPERTY_VIEW_ANY`, `PROPERTY_UPDATE_ANY`, `PROPERTY_REVIEW`, `PROPERTY_PUBLISH`
  and `PROPERTY_LEGAL_REVIEW` (a super-admin has them). The password comes from `SEED_ADMIN_PASSWORD`
  or a prompt.
- Re-runnable: properties whose name already exists are skipped. Delete them in the dashboard to
  re-create them.
- Photos and the brochure are generated by the script (standard library only). Videos are rendered by
  `make_demo_video.swift`, compiled once with `swiftc` (macOS); elsewhere, or with `--no-video-files`,
  they are skipped. `--video-url https://www.youtube.com/watch?v=...` adds an external video link to
  every property.
- `--api` defaults to `http://localhost:8080`; other hosts are refused unless `--allow-remote` is given.
- It uses about 7 uploads and 4 status changes per property, well within the per-hour rate limits.
